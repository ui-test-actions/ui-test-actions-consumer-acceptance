# Isolated P2pKit link fault tests

These runs used the same pinned Android and Apple Silicon iOS P2pKit samples and `a56957b05ce72ed15c0c35daad572a2add0d173e` as the [paired app acceptance](../paired-lan/). A separate Android-side controller shaped the packets forwarded by the app LAN bridge. The two runner UI sessions used their own Quick Tunnels and authentication.

- The first trial applied a 500 ms one-way link delay. Thirteen independent native ICMP observations across two active intervals measured 1,078–1,354 ms round trip. The app observer moved away from the Android receiver timeline before it could verify the delayed message. [Run 44851212389](https://github.com/ui-test-actions/ui-test-actions-consumer-acceptance/actions/runs/44851212389) · [Delay samples](initial-observation/partial-delay-measurement.json)
- The next trial reached a native SwiftUI accessibility tree, then timed out capturing the Simulator framebuffer before it could publish the iOS UI connection. An independent run qualified the [AXe UIKit configuration](../mobile-adapters/axe-ios/). [Run 44853371821](https://github.com/ui-test-actions/ui-test-actions-consumer-acceptance/actions/runs/44853371821)
- A new visible-backend run hit an Ubuntu package-index failure before the emulator started. The independent consumer added bounded refresh and package installation retries. [Run 44854334430](https://github.com/ui-test-actions/ui-test-actions-consumer-acceptance/actions/runs/44854334430) · [Consumer correction](https://github.com/ui-test-actions/ui-test-actions-consumer-acceptance/commit/ddff05f07ca62dfb338db8a0d037e199d8e6d59b)
- After that correction, both hosted jobs finished successfully. Each real app discovered the peer and showed an authenticated connection. The Android app sent `BASIL` and the iOS app displayed it. The iOS composer moved out of view while preparing the reverse-direction fault experiment. The external client confirmed a baseline reset, and a bearer from the other UI session received HTTP 401 on the network-control endpoint. [Run 44854676658](https://github.com/ui-test-actions/ui-test-actions-consumer-acceptance/actions/runs/44854676658) · [Connection, message and authorization evidence](last-visual-attempt/)

## Fault and recovery acceptance

In the final trial Android sent both test messages, leaving iOS in the receiver view. iOS displayed `Android-433 -> CEDAR` while the 500 ms one-way delay profile was active. The observer exercised a separate 25% loss profile. During the leased full outage, the Android app displayed **No peers connected** and both UI endpoints accepted authenticated requests. After automatic lease expiry restored forwarding, the apps re-paired through discovery and iOS displayed `Android-433 -> MAPLE`. The runner accepted an explicit final reset, and the other device's bearer received HTTP 401 on the Android network-control endpoint. [Run 44856486177](https://github.com/ui-test-actions/ui-test-actions-consumer-acceptance/actions/runs/44856486177) · [App assertions and screenshots](final/) · [Independent native measurements](final/native-summary.json)

Seventeen delayed ICMP samples measured 1,039–1,178 ms round trip. The loss profile delivered two of three probes. None of the nine outage probes returned. After restoration, nineteen probes measured 49–213 ms round trip. The relay counted 114 deliberate drops across the trial. [Timestamped native probes](final/native-delivery.txt) · [Relay counters](final/traffic.json)

The first outage assertion in this run assumed that the accessibility node containing the Android status text inherited a disabled button attribute. A fresh tree showed the status text on an enabled child node. The observer re-paired the live apps, repeated only the outage stage, and verified the exact text together with the active outage generation. [Profile ledger and preliminary attempt](final/network.json)

## Reproduce

1. Dispatch the independent [paired workflow](../../../.github/workflows/mobile-lan-transport.yml) in `network` mode with the visible iOS backend, sample build runs `44727058613` and `44733760941`, and two different session token digests. Connect to the running jobs with [the published client instructions](https://github.com/ui-test-actions/ui-test-actions/tree/a56957b05ce72ed15c0c35daad572a2add0d173e#connect-and-hand-the-session-to-an-agent).
2. Start both real apps, verify each discovers the other by name, and connect from the discovered list. Prepare the Android composer and the iOS receiving timeline. Use small Simulator scrolls when the diagnostic log is open.
3. Set a 500 ms one-way delay with 25 ms jitter and a 512 kbit/s rate cap. Send a unique Android payload and verify the exact iOS receiver line while the same profile generation is active. Set a separate seeded 25% loss profile. Reset, then confirm the apps are connected before creating a 48-second offline lease.
4. While the offline generation is still active, confirm both UI endpoints respond and Android displays **No peers connected**. Wait for a new generation with a zero remaining lease. Re-pair through the discovered peer, send a different Android payload, and verify the new iOS receiver line. Keep the app assertions and current profile records, then use the pinned [native evidence summarizer](https://github.com/ui-test-actions/ui-test-actions/blob/a56957b05ce72ed15c0c35daad572a2add0d173e/verification/mobile-lan/network-evidence.py) on the Android `delivery.txt` and `traffic.json` artifact files. [Profile command reference](https://github.com/ui-test-actions/ui-test-actions/blob/a56957b05ce72ed15c0c35daad572a2add0d173e/docs/environment.md#isolated-mobile-lan-profiles)
