# Independent Cloudflare Named Tunnel and Access acceptance

The independent consumer used `ui-test-actions/ui-test-actions@a56957b05ce72ed15c0c35daad572a2add0d173e` on a GitHub-hosted Linux runner. Its temporary `uitest-consumer.abdelrahmanfahmy.dev` route had a dedicated connector, exact-host Access application, scoped service credential pair, and independent per-session UI bearer. The only ingress to the application was the tunnel route to `127.0.0.1:8787`. The workflow used the published Action directly. [Consumer configuration](../../../.github/workflows/named-tunnel.yml)

- An external agent authenticated, inspected the ready app and changed its state. A fresh client reconnected to the same session and got the cached result for a repeated operation. The runner independently checked the exact Unicode text arrived once. Missing and invalid Access credentials returned HTTP 403 and 401 respectively on both the root and session endpoint. Access accepted the correct service credentials only for their application. The runner rejected wrong or missing UI bearers and a mismatched session ID.
