## Named Tunnel and Access

The dedicated publisher test hostname was reserved for one job at a time by the workflow and used a separate hosted observer. Valid Access service credentials and the UI bearer admitted the native action. Missing Access returned 403, invalid Access returned 401, and a stale session identity returned 409. ## Concurrent stress

Four concurrent hosted sessions each took 168 requests from 12 concurrent clients in two rounds. The four cases returned 604 HTTP 200 and 68 HTTP 429 backpressure responses and had 76 valid native frame captures. The second round returned 590 HTTP 200, 80 HTTP 429 with `The session is busy`, and two transient Windows screenshot HTTP 502 responses. Fresh clients still authenticated to each original session. The per-platform replay checks reproduced a lost HTTPS response at the observer, a readback of the applied write, 96 intervening operations, refusal of both same-payload and conflicting evicted IDs, and preservation of the newer clipboard value across retries. The earlier five-platform native crash/relaunch, three desktop freeze/recovery runs, and the same-release Quick Tunnel, private transport, SDK, inspector, and Appium diagnostics remain in the [v3.0.1 baseline report](../stability-v3.0.1/). The local Linux session hosting Veyra performed 560 reads and 28 captures. It settled to three threads and four file descriptors at every sample. Its Python server RSS ranged from 26,724 to 27,052 KiB during the short observation. ## Reproduce

Use the independent consumer's [desktop workflow](../../.github/workflows/desktop.yml), [mobile lifetime workflow](../../.github/workflows/mobile-lifetime.yml) or [mobile LAN workflow](../../.github/workflows/mobile-lan-transport.yml). Set the dispatch input `duration` to 60 for a lease test. The workflows pass it through as `duration-minutes`. Use `v301-stress` for the fixtures. The Android stock-emulator run used `stock-android-e2e` plus the prebuilt Parlor package, and its second run used `v301-parlor-offline`. Provision unique bearers, supply only their SHA-256 digests to the Quick Tunnel workflows and keep each downloaded connection record private during the lease. The external soak reads `connection/connection.json` and `token` inside each platform's directory. It reads a token from the Windows or macOS sibling directory to verify cross-session authentication rejection. The observer and stress client use the published Action checkout, its `verification` directory on `PYTHONPATH`, and Pillow for pixel checks. [Connection instructions](https://github.com/ui-test-actions/ui-test-actions/tree/0c818c5d72e8c30c59bd1287c330a40392bf8e89#connect-and-hand-the-session-to-an-agent) · [Soak client](hour/observe-hour.py) · [Transport setup](https://github.com/ui-test-actions/ui-test-actions/blob/0c818c5d72e8c30c59bd1287c330a40392bf8e89/docs/transports.md)

The Named Tunnel exercise used a dedicated hostname with service authentication, a per-run UI bearer, separate host and observer jobs, and a one-job-at-a-time rule for the route. The Named Tunnel checks used hosted Linux. The LAN exercise controlled application traffic independently on the dedicated private overlay. The three-peer Linux exercise built the pinned CLI with `:p2p-sample-desktop:installDist` and used a disposable network namespace with an isolated multicast-capable veth pair. P2pKit intentionally excludes interface names starting with `ap` from LAN selection, so the test used `eth-lan0`. [Three-peer observer](p2p/three-linux-peers.py) · [Sanitized native events](p2p/three-linux-peer-extract.txt).

Every application repository was used read-only. The two issue references above are updates to existing application issues. The framework's 109 regression tests passed at the released commit. The observed failures remain scoped to the named applications or transient transport responses. This validation added consumer test workflows and evidence without a framework source change or new release. [Current release](https://github.com/ui-test-actions/ui-test-actions/releases/tag/v3.0.1)
